# 尺寸与坐标标准 v2.0.0

## 适用范围

只包含JJ-OD35-SAMPLE-001这一把35°菱形外圆刀，r02/r04/r08为同一把刀的鼻圆变体。所有线性尺寸为教学近似默认值，不是厂家核验或从图片透视测出的尺寸。原专业样板和旧六类简化刀具没有重新计入本资源库。

## 模型局部坐标

右手系、毫米。原点为刀杆后端截面中心；+X沿刀杆宽度、+Y从刀头指向后端、+Z从刀杆底面指向刀片顶面。后端Y=0，刀头在负Y。这个基准是模型装配约定，不是制造商安装标定，更不是S205A机床轴或G代码坐标。

从原样板局部mm坐标到本标准：`p标准 = p原 − (0,65,−5)`。原模型不修改。

安装参考点为(0,0,0)，默认安装矩阵为单位矩阵。JSON矩阵全部按Three.js的列主序记录、列向量右乘；宿主提供刀座到场景的实际装配变换，不从型号或刀片外形推断机床方向。

## 文件单位和换算

GLB采用glTF2的米制、Y向上坐标。资源模块提供的模型根节点、元数据和接口输出均采用毫米、Z向上。模块内部只做一次：

`p局部mm = Rx(+90°) × S(1000) × pGLB米`

即原始GLTFLoader世界点 `(x,y,z)` 转为 `(1000x, −1000z, 1000y)`。元数据geometryUnits中提供完全相同的矩阵。

宿主若采用毫米，可直接挂载模块返回的根节点；宿主若采用米，应把所有工具根节点放进一个scale=0.001的装配父节点，并保持内部安装参数仍以毫米输入。此时localToWorld返回的坐标单位随宿主世界为米。不得对返回根节点再乘1000。

## 尺寸和位置

metadata/tool.json是唯一标准元数据入口。顶层holderDimensions/cuttingTipPosition/noseArcCenter/boundingBox是默认r04的便利值；切换版本必须读取noseRadiusVariants[key]下的值。

- 刀杆宽约10mm、高约10mm，后部基准长度65mm；全长由实际刀杆包围范围计算，约76.78～78.10mm，逐版本记录，不能把65mm误当总长。
- 刀片厚度2.6mm；顶面标准Z=6，底面Z=3.4。垫座底面Z=2.8、顶面Z=3.4；刀座腔底面Z=2.8。贴合平面为设计接触，非错误穿透。
- 刀片平面中心位于X=−1、Y=−70；平面旋转−18°为演示安装姿态。insertInstallation.matrixColumnMajor从未旋转刀片坐标映射到模型局部系，厚度方向仍按源定义。
- 35°是刀片两直边的尖角，不是主偏角。approachAngle和hand保留null待确认。
- cuttingTipPosition为倒角后选定的真实网格刃口基准点，不是模型中心、原点或虚拟尖角。它只是当前模型的参考接触点，具体切削接触仍取决于工件法向与安装姿态。
- noseArcCenter是设计顶面圆弧中心(Z=6)，nominalNoseArcApex是倒角前的圆弧顶点；0.025mm刃口倒角后，实际刀尖基准与该设计圆弧点不同。圆弧半径通过外侧壁圆弧的XY投影核验，不能拿倒角点到顶面中心的三维距离直接当R。
- 原脚本的R参数还影响配套座腔和刀头避让前端；本轮保留现有形体，因此三个版本刀杆全长也有差异，元数据没有假设共用同一包围盒。

整体包围盒是所有5个实体在未装配局部系的最小/最大坐标。坐标轴、标记球和包围盒显示线不属于实体，也不进入部件统计或碰撞候选列表。

## 几何保持与优化

standardize.py读取原.blend，把原装配姿态烘焙到新安装基准，再导出GLB；没有重新建刀具、没有降低刀尖圆弧细分、没有增加其他刀具。移除了原先只负责mm→m的空父节点，5个实体的名称与componentRole保持独立。文件无纹理、摄像机、灯光和动画，无Draco/Meshopt运行时依赖。

每版约517KiB、5个网格、4个材质、8416～8422个三角面。未为节省少量面数破坏鼻圆或布尔孔。服务器采用正确的HTTP gzip后每版约131KiB；这属于传输压缩，解压后仍是同一GLB，不能把.gz文件不带Content-Encoding地交给GLTFLoader。
